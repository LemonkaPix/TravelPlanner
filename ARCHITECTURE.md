# TravelPlanner — architecture

React Native application built with Expo SDK 57, TypeScript and Expo Router.
The first version plans one journey from home to university, entirely offline.

## Feature index and entry points

| Feature | Entry point | Responsibility |
| --- | --- | --- |
| App bootstrap | `package.json` → `expo-router/entry` → `src/app/_layout.tsx` | Router, status bar and screen background |
| Planner screen | `src/app/index.tsx` → `src/features/planner/PlannerScreen.tsx` | Polish form, departure result, timeline and explicit save action |
| Calculation and validation | `src/features/planner/plan.ts` | Local date/time parsing, duration validation, arrival and departure timestamps |
| Local persistence | `src/features/planner/useStoredPlan.ts` | Load/save one validated plan using AsyncStorage |
| Shared form field | `src/components/FormField.tsx` | Accessible labelled text input and inline validation |
| Visual tokens | `src/constants/theme.ts` | Colours, platform typography and shared text styles |
| Expo configuration | `app.json`, `tsconfig.json`, `package.json` | SDK 57 (Expo Go on Android Play Store), native identity, plugins and strict TypeScript |

## Data flow and contracts

`AsyncStorage → useStoredPlan → PlannerScreen → calculatePlan → result/timeline`.
An explicit save writes the current valid form back to AsyncStorage. The form
stays unavailable until loading completes, preventing hydration from replacing edits.
Storage failures are shown to the user; calculations remain available offline.

`PlanInput` contains strings: origin, destination, date (`DD.MM.YYYY`), time
(`HH:mm`), travelMinutes and bufferMinutes. Storage uses the versioned key
`travelplanner.plan.v1`; stored values must pass the same validation as form input.
Past plans are retained and clearly labelled rather than silently moved to tomorrow.

Departure = class start − safety buffer − door-to-door travel duration.
Travel includes walking and waiting and is entered manually. All timestamps use
the device's local timezone; departure can fall on the previous calendar day.
Nonexistent local times during daylight-saving transitions are rejected.

## Boundaries

No backend, authentication, location access, routing API, traffic data or scheduled
notifications. The destination is a user-entered label, not a geocoded address.
Changing the device timezone reinterprets the saved local date and time.
Native `ios/` and `android/` projects are generated by Expo and are not committed.
Dependencies are managed by npm and pinned by `package-lock.json`.
